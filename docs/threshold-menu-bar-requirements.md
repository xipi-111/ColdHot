# ColdHot 菜单栏阈值显示需求

- 状态：已批准
- 批准日期：2026-08-17
- 适用版本：官网版

## 目标

用户可为具有实时告警价值的性能参数单独启用阈值。当参数持续达到阈值时，ColdHot 的菜单栏图标自动替换为紧凑的双行读数；参数恢复后自动回到简易图标。

## 配置范围

阈值开关独立于一级卡片和详细项目的展示开关。用户不需要为了告警而一直显示或展开对应卡片。

可配置的一级指标：

- CPU 使用率
- GPU 使用率（官网版）
- 内存使用率
- 网络下载、上传速度
- 磁盘读取、写入速度（官网版）
- 系统热状态
- 电池低电量

可配置的详细指标：

- CPU、GPU、内存、NAND、电池、风道、Wi-Fi 和电源管理温度（官网版，按设备可用传感器显示）
- 风扇转速（官网版）
- 整机功率和电池功率（官网版）

不提供阈值的项目包括循环次数、累计流量、累计磁盘读写、磁盘容量、显示器刷新率和进程排行。

## 触发与恢复

- 连续 2 次采样达到阈值后触发，避免瞬时峰值误报。
- 高值告警在读数低于阈值约 5% 的恢复线后开始恢复计数。
- 电池低电量告警在读数高于阈值约 5% 的恢复线后开始恢复计数。
- 连续 3 次采样处于恢复范围后解除告警。
- 设备不提供某项读数时不触发告警，并保持设置不变。

## 菜单栏显示

- 无告警时显示现有简易图标，并继续根据系统热状态选择图标档位。
- 有告警时使用上下两行布局，同一时刻只显示一个指标。
- 上方显示较大的实时数值和必要的紧凑单位；下方显示较小的监控对象或方向。
- 下方不重复“温度”“使用率”等指标类别，用户通过数值单位识别含义。
- 示例：`94° / CPU`、`42° / 电池`、`92% / CPU`、`85% / 内存`、`3280 / 风扇 1`、`18W / 整机`、`12M/s / 下载`。
- 多个指标同时告警时每 5 秒轮换一个。
- 新触发的指标立即优先显示一次，之后进入轮换。
- 指标恢复后从轮换队列移除；最后一个告警解除后恢复简易图标。

## 采样与资源控制

- 一级指标沿用用户选择的 1、2 或 5 秒刷新间隔。
- 仅用于阈值的温度和功率详细项在未告警时每 5 秒后台采样一次。
- 某个详细指标触发后，按用户的正常刷新间隔采样，直到恢复。
- 已展开卡片的详细项目仍按正常刷新间隔采样。
- 阈值功能关闭时不得引入额外传感器采样。

## 发行边界

- 本功能仅面向官网版实现、测试和发布，提供全部可用阈值项目。
- App Store 版已停止维护，本次不构建、不提交，也不更新审核资料。
- 仓库中已有的 App Store 配置继续保留，但不属于本需求的交付范围。

## 验收标准

- 用户可以逐项启用阈值并修改阈值数值。
- 阈值配置在应用重启后保留，恢复默认会关闭全部阈值并恢复推荐数值。
- 达到和恢复计数符合 2 次触发、3 次恢复规则。
- 菜单栏告警为上下布局，不出现横向“类型 + 数值”或 `+N` 计数。
- 多告警严格每 5 秒轮换，新告警立即优先显示。
- 官网版可完整构建，现有 App Store 配置不作为本次验收项。
- 完成构建验证与短时运行资源占用检查。
