# ColdHot 设置界面 Apple Music 风格改版设计

日期：2026-08-18
状态：待用户文档确认
适用范围：ColdHot 官网分发版设置窗口，不改变监控、阈值、更新或菜单面板业务逻辑

## 1. 背景与问题

当前 1.3.0 (14) 设置窗口虽然采用了 `NavigationSplitView` 和系统侧栏列表，但最终呈现仍是普通设置页：

- 左侧是深色实底窄栏，缺少 macOS 26 Apple Music 的浮层材质和空间层级；
- 系统蓝色满宽选中态与 ColdHot 品牌不一致；
- 顶部仍出现居中的 “ColdHot Settings” 标题；
- 右侧大量使用默认 grouped Form，分组卡片同质、内容密度偏机械；
- 当前 1040×848 默认窗口对设置任务偏大，部分页面产生明显空白；
- 仅依赖框架默认外观，无法稳定复现用户指定的 Apple Music 视觉。

用户已经通过并排草图确认以下方向：

- 采用 A：Apple Music 式窗口结构；
- 采用 A1：保留 ColdHot 绿色作为强调色，不复制 Apple Music 粉红品牌色；
- 默认窗口收窄为 920×720，最小尺寸 860×680；
- 侧栏、内容层级、交互和验收标准均按本文执行。

## 2. 体验目标与视觉主张

因为 ColdHot 用户需要快速理解和调整监控设置，设置窗口应当**平台原生但具有 ColdHot 识别，信息紧凑但不拥挤**。主要通过 Apple Music 式玻璃导航层、稳定的双栏结构、清晰的标题与分组节奏表达；日常设置操作保持安静、直接和可预测。它不能再像通用 SwiftUI 设置模板，也不能通过过度玻璃、发光或大面积品牌色制造“高级感”。

目标品质：

- 原生、克制、清晰、稳定；
- 具有 macOS 26 的导航层级，但兼容 macOS 14–15；
- 保留 ColdHot 绿色识别；
- 设置内容比当前版本更紧凑，但所有控件仍易于扫描和操作。

反目标：

- 不直接复制 Apple Music 的粉红色、搜索、资料库或播放列表结构；
- 不把所有右侧内容做成玻璃；
- 不保留系统蓝色满宽选中态；
- 不使用居中的窗口标题；
- 不通过切换页面动态改变窗口尺寸。

## 3. 空间结构

### 3.1 窗口

- 默认内容尺寸：920×720；
- 最小内容尺寸：860×680；
- 用户仍可按 macOS 习惯放大窗口；
- 所有设置页共享同一尺寸，不因页面切换缩放窗口；
- 使用全尺寸内容视图，隐藏居中窗口标题和多余工具栏；
- 红黄绿交通灯位于侧栏上方区域，并与窗口圆角保持协调间距。

### 3.2 侧栏

- 侧栏固定宽度 204pt，在默认和最小窗口尺寸下都不压缩；
- 侧栏属于导航层，内容区属于主内容层，两者通过材质、轻微分隔和空间层级区分；
- 顶部保留简短分组标题“设置”；
- 导航顺序不变：外观、指标、阈值提醒、通用、关于；
- 底部保留 ColdHot 应用标识和版本，但不放关键操作；
- 侧栏固定，不随右侧内容滚动。

### 3.3 主内容区

- 页面标题位于主内容左上角，不放入工具栏；
- 内容使用统一最大阅读宽度，避免在大窗口中无限拉伸；
- 以标题、距离、轻量表面和细分隔线组织关系，不依赖大量等权卡片；
- 右侧只有内容超出可用高度时才滚动，未超出时不显示滚动条；
- “外观”页保留设置与即时预览双栏，真实 370px 菜单画布等比缩放到可用宽度，裁切范围和菜单面板一致。

## 4. 视觉系统

### 4.1 材质

- macOS 26：侧栏使用系统提供的玻璃导航材质；
- macOS 14–15：使用语义为 sidebar 的系统视觉效果材质作为兼容降级；
- 玻璃只用于导航层，不用于右侧所有内容表面；
- 开启“降低透明度”时，侧栏改为不透明的系统背景色，禁止保留模糊半透明。

### 4.2 颜色

- 强调色使用 ColdHot 绿色；
- 选中行使用中性半透明底，绿色只用于当前项目的图标和文字；
- 状态成功可继续使用绿色，警告和错误保持各自语义色；
- 不用绿色装饰所有按钮、分隔线或卡片，避免失去语义重点；
- 深色和浅色模式分别根据实际背景校验对比度。

### 4.3 字体与密度

- 使用系统字体，不引入自定义字体；
- 页面标题使用 34pt，作为第一视觉焦点；
- 分组标题使用 13pt semibold；
- 导航和设置正文保持系统可读字号；
- 数值列和状态列对齐，避免页面之间出现不同基线；
- 分组内部行高 40pt，侧栏行高 32pt；
- 圆角、边框、分隔线只使用少量统一层级。

### 4.4 交互状态

侧栏项目必须具备：

- 默认；
- 悬停；
- 按下；
- 选中；
- 键盘焦点；
- 非活动窗口状态。

系统控件继续使用原生 Toggle、Picker、Slider 和 Button，不为追求外观重新实现交互控件。

## 5. 组件与实现边界

### 5.1 SettingsShellView

负责窗口级双栏布局、侧栏宽度、主内容区域和页面切换。它替代当前依赖默认外观的 `NavigationSplitView` 表面，但不接管业务状态。

### 5.2 SettingsSidebar

负责：

- 五个页面入口；
- 自定义中性选中底和 ColdHot 绿色强调；
- 鼠标、键盘和辅助功能状态；
- 底部应用信息；
- macOS 26 与旧系统材质切换。

页面选择继续由 `SettingsPage` 和 `selectedPage` 驱动。

### 5.3 SettingsSectionSurface

提供右侧设置分组的统一表面、内边距和分隔线。现有 Toggle、Picker、Slider、Button 继续作为其内容，不复制业务绑定。

### 5.4 SettingsWindowConfigurator

负责真实 Settings Scene 窗口配置：

- 默认与最小尺寸；
- 全尺寸内容；
- 隐藏标题与无功能工具栏；
- 正确的标题栏透明度、窗口背景和交通灯布局；
- 窗口重新激活后配置仍然有效。

必须在真实安装版 Settings Scene 中验证，不能只依赖测试窗口。

### 5.5 页面内容

五个页面保留现有业务内容：

- 外观：背景图片、遮罩、卡片透明度、主/辅助文字、进度条、实时预览；
- 指标：预设、一级指标和详细项；
- 阈值提醒：通知和阈值设置；
- 通用：更新、Dock 快捷控制和采样；
- 关于：版本、设备能力和 ColdHot 运行影响。

本轮不新增、删除或改变设置项含义。

## 6. 页面切换与滚动

- 侧栏选择后立即切换页面；
- 主内容允许一次短促、低位移或纯透明度淡入；
- 动画不得改变窗口尺寸、侧栏位置或滚动容器几何；
- 开启“减少动态效果”时取消淡入，直接切换；
- 每个页面保留独立、可预测的滚动行为；
- 侧栏不滚动，右侧不足一屏时不产生滚动范围或滚动条；
- 键盘可以在侧栏项目间导航并激活页面。

## 7. 兼容性与辅助功能

- 最低系统版本保持 macOS 14；
- macOS 26 使用新设计系统提供的导航玻璃；
- macOS 14–15 使用 `NSVisualEffectView` 的 sidebar 语义材质；
- `accessibilityReduceTransparency == true` 时使用不透明背景；
- `accessibilityReduceMotion == true` 时禁用页面切换动画；
- VoiceOver 能朗读侧栏组、当前选中页面、设置项标签和值；
- 键盘焦点必须清晰可见，不能只依赖颜色区分；
- 深色和浅色模式均需验证文字与控件对比度。

## 8. 错误与降级处理

- macOS 26 玻璃 API 不可用时自动走旧系统材质，不显示空白或透明侧栏；
- 如果窗口配置因 Settings Scene 生命周期被系统重置，在窗口激活和尺寸变化时重新应用幂等配置；
- 自定义背景图片读取失败、通知权限失败等现有错误路径保持不变；
- 预览缩放只影响显示尺寸，不改变实际设置值或图片裁切数据；
- 最小尺寸下若某页内容超高，仅右侧垂直滚动，不允许水平裁切。

## 9. 验收与测试

### 9.1 自动化检查

- 组件级检查侧栏五个入口、选择状态和页面绑定；
- 窗口检查默认尺寸 920×720、最小尺寸 860×680；
- 检查工具栏不可见、标题不可见、全尺寸内容配置；
- 检查 macOS 26/旧系统材质分支可编译；
- 检查降低透明度和减少动态效果分支；
- 检查外观预览仍使用真实 370px 菜单画布及相同裁切；
- 运行项目全部现有脚本检查和 Direct 构建。

### 9.2 视觉验收

分别渲染并检查：

- 深色 920×720；
- 浅色 920×720；
- 深色 860×680；
- 浅色 860×680；
- 外观、指标、阈值提醒、通用、关于五页；
- 默认、悬停、焦点、选中、非活动窗口状态；
- 降低透明度与减少动态效果状态。

视觉检查重点：

- 红黄绿按钮位置与侧栏几何协调；
- 不出现 “ColdHot Settings” 居中标题；
- 不出现系统蓝色满宽选中态；
- 右侧内容无裁切、无无意义大片留白；
- 侧栏和右侧内容的层级与用户确认的 A1 草图一致；
- 各页面的分组、行高、字体和圆角无漂移。

### 9.3 真实安装版验收

- 构建本地测试版并安装；
- 从菜单面板打开真实设置窗口；
- 验证窗口成为最前焦点；
- 反复关闭、打开和切换页面，确认标题栏配置不会被 Settings Scene 恢复；
- 调整至最小尺寸，确认没有水平裁切；
- 最终由用户进行视觉确认；本轮不发布 GitHub。

## 10. 非目标

- 不修改菜单面板视觉或动画；
- 不修改监控采样、阈值、通知、更新或 Dock 控制逻辑；
- 不新增搜索功能；
- 不复制 Apple Music 的粉红色、内容结构或品牌资产；
- 不改变应用最低系统版本；
- 不在本轮发布正式版本。

## 11. 参考依据

- 用户提供的 macOS 26 Apple Music 截图：作为已发货产品的结构、密度和材质目标；只迁移导航层级、空间节奏和交互原则，不复制品牌表达。
- [Apple Human Interface Guidelines — Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)：侧栏属于主要导航区域，在新设计中可浮于 Liquid Glass 导航层；图标颜色应有明确用途。
- [Apple Human Interface Guidelines — Layout](https://developer.apple.com/design/human-interface-guidelines/layout)：导航组件与内容处于不同空间层级，布局需考虑覆盖与安全区域。
- [WWDC25 “Meet Liquid Glass”](https://developer.apple.com/videos/play/wwdc2025/219/)：玻璃应主要保留给导航层，不应铺满内容层；材质需响应降低透明度、提高对比度和减少动态效果。
- [WWDC25 “Build an AppKit app with the new design”](https://developer.apple.com/videos/play/wwdc2025/310/)：macOS 26 的侧栏以浮动玻璃窗格呈现；自定义玻璃内容应使用系统 API，并正确组织内容层级。
- [Apple `NSVisualEffectView` 文档](https://developer.apple.com/documentation/appkit/nsvisualeffectview)：旧系统侧栏降级应使用语义为 sidebar 的系统材质，而不是按表面颜色选择材质。
- [Apple `accessibilityReduceTransparency` 文档](https://developer.apple.com/documentation/swiftui/environmentvalues/accessibilityreducetransparency)：启用降低透明度时，窗口背景应不透明。

## 12. 完成定义

只有在以下条件全部满足时，改版才算完成：

- 用户确认的 A1 视觉和 920×720 比例在真实安装版中成立；
- 五个设置页面保持功能完整；
- macOS 26 与 macOS 14–15 路径均可构建；
- 深色、浅色、最小尺寸和辅助功能状态通过检查；
- 顶部标题、系统蓝色选中态和不必要的空白被消除；
- 自动化检查、Direct 构建和真实 Settings Scene 验证全部通过；
- 用户完成最终视觉确认。
